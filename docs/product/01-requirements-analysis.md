# 需求分析与优先级

版本: v0.1
日期: 2026-05-26
阶段: Phase 0 / 立项与需求分析

## 1. 产品定位

Webnovel IDE 是一个面向中文网文创作的商业级长篇连载创作平台，帮助作者完成从开书、设定、大纲、章节写作、AI 辅助修改、连续性检查到发布准备的完整工作流。

它不是单纯的 AI 写作聊天框，也不是普通笔记软件，而是围绕“持续连载”和“商业转化”设计的创作 IDE。

一句话定位：

> 面向网文作者的长篇连载 IDE，帮助作者管理作品工程、稳定生产章节，并用 AI 维护设定、节奏和商业化表达。

## 2. 核心目标

### 2.1 用户目标

- 降低新手作者从想法到开书的门槛。
- 帮助作者稳定日更，减少断更和卡文。
- 管理长篇作品中的人物、设定、伏笔、时间线和章节状态。
- 提升章节可读性、爽点密度、留存表现和平台适配度。
- 让作者在 AI 辅助下保持自己的创作主导权。

### 2.2 商业目标

- 形成可订阅的专业创作工具，而不是一次性提示词产品。
- 用长篇记忆、连续性检查、项目化管理建立护城河。
- 同时服务个人作者和中小型网文工作室。
- 后续可扩展为模板市场、素材库、拆书系统、协作系统和平台数据分析系统。

## 3. 目标用户

### 3.1 新手作者

特征：

- 有题材兴趣和表达欲，但缺少完整开书方法。
- 容易卡在书名、简介、前三章、大纲和人物动机。
- 对 AI 接受度高，但容易被 AI 带偏。

核心需求：

- 开书引导。
- 题材与卖点评估。
- 黄金三章规划。
- 章节卡片生成。
- 初稿续写与润色。

### 3.2 成长期作者

特征：

- 已经能写章节，但长篇管理能力不足。
- 经常出现设定遗忘、伏笔丢失、角色状态混乱。
- 对效率和稳定更新有强需求。

核心需求：

- 作品工程管理。
- 人物与设定库。
- 章节树和更新进度。
- 伏笔、时间线、连续性检查。
- AI 局部改写、节奏诊断、对白优化。

### 3.3 职业作者 / 工作室

特征：

- 对稳定产能、风格一致、协作流程和商业数据更敏感。
- 可能有多个项目并行、多人分工、编辑审核。

核心需求：

- 多项目管理。
- 多人协作。
- 权限和版本控制。
- 数据看板。
- 模板化生产。
- 商业化诊断。

MVP 优先服务：新手作者和成长期作者。

工作室能力作为中后期商业化增强方向。

## 4. 核心使用场景

### 4.1 从零开书

用户输入题材、主角、卖点或一句灵感，系统辅助生成作品立项卡、人物卡、世界观草案、前三章方向和章节节奏建议。

### 4.2 管理长篇作品

用户在作品项目中维护卷、章节、人物、设定、势力、伏笔、时间线和写作进度，避免长篇连载后期失控。

### 4.3 日常章节写作

用户打开章节编辑器，查看本章目标、相关人物、前文摘要和待回收伏笔；写作过程中可让 AI 续写、润色、改对白、补冲突或压缩废话。

### 4.4 连续性检查

系统根据已有设定、人物状态、前文章节摘要和伏笔记录，检查当前章节是否存在设定冲突、人物 OOC、时间线错误和未解释跳跃。

### 4.5 发布前优化

系统检查章节标题、开头钩子、结尾悬念、爽点密度、敏感词、简介、标签和平台适配度。

### 4.6 素材学习与迁移

用户导入本地素材或拆书笔记，系统帮助整理情节模型、人物机制、节奏结构和可迁移写法，但避免直接复刻原作品表达。

## 5. 需求分层

### P0: MVP 必须具备

P0 目标：证明用户可以在平台里创建作品、管理章节、写正文，并获得基础 AI 辅助。

| 模块 | 需求 | 价值 |
| --- | --- | --- |
| 作品管理 | 创建、编辑、删除作品 | 建立项目化写作入口 |
| 章节管理 | 卷、章节树、章节状态 | 支撑长篇结构 |
| 正文编辑器 | 写作、自动保存、字数统计 | 核心写作体验 |
| 人物库 | 创建人物卡、维护基础设定 | 为 AI 和连续性打基础 |
| 设定库 | 世界观、势力、等级、道具等记录 | 管理长篇设定 |
| AI 助手 | 续写、润色、总结、改写 | 提升写作效率 |
| 上下文面板 | 本章目标、相关人物、相关设定 | 让写作时信息可见 |
| 导出 | TXT / Markdown 导出 | 满足发布前流转 |

### P1: 网文 IDE 核心差异化

P1 目标：从“写作工具”升级为“长篇连载 IDE”。

| 模块 | 需求 | 价值 |
| --- | --- | --- |
| 章节卡 | 每章目标、冲突、爽点、钩子、出场人物 | 把章节生产结构化 |
| 大纲管理 | 主线、卷纲、支线、阶段目标 | 支撑长期创作 |
| 伏笔管理 | 已埋、待回收、已回收、遗忘风险 | 解决长篇丢伏笔 |
| 时间线 | 事件顺序、角色位置、状态变化 | 降低连续性错误 |
| 连续性检查 | 设定冲突、人物状态冲突、前后矛盾 | 建立产品护城河 |
| 节奏诊断 | 水章、信息过载、冲突不足、爽点过远 | 提升读者留存 |
| 角色一致性 | 口吻、动机、行为逻辑检查 | 减少 OOC |

### P2: 商业化增强

P2 目标：帮助作者写得更像平台可卖内容。

| 模块 | 需求 | 价值 |
| --- | --- | --- |
| 开书评估 | 题材、卖点、受众、风险分析 | 降低选题失败率 |
| 黄金三章分析 | 开篇吸引力、主角动机、期待感、冲突 | 提升开书留存 |
| 书名简介 | 多版本生成和评分 | 提升点击率 |
| 标签建议 | 平台标签、题材标签、人群标签 | 提升平台适配 |
| 发布检查 | 敏感词、标题、章节钩子、结尾悬念 | 降低发布风险 |
| 更新计划 | 日更目标、存稿量、断更风险 | 支撑连载稳定性 |
| 数据反馈 | 收藏、追读、评论、完读等数据记录 | 用数据调整创作 |

### P3: 商业级平台能力

P3 目标：服务职业作者、工作室和生态扩展。

| 模块 | 需求 | 价值 |
| --- | --- | --- |
| 多人协作 | 作者、编辑、审稿、运营角色 | 支撑团队生产 |
| 权限管理 | 项目权限、章节权限、评论权限 | 商业协作必备 |
| 版本管理 | 章节历史、版本对比、回滚 | 专业编辑流程 |
| 批注审稿 | 行内评论、修改建议、状态流转 | 支撑编辑协作 |
| 素材库 | 本地素材、拆书卡、桥段模型 | 建立创作资产 |
| 模板市场 | 题材模板、章节模板、人物模板 | 增强商业生态 |
| 插件系统 | 第三方扩展、平台导出插件 | 长期生态能力 |
| 桌面端 | 本地文件、离线写作、系统级体验 | 提升专业工具感 |

## 6. 非功能需求

### 6.1 性能

- 章节编辑输入延迟应接近本地编辑器体验。
- 作品达到 300 万字时，章节树、搜索、设定查询仍应可用。
- AI 请求应异步执行，不阻塞用户写作。

### 6.2 可靠性

- 正文自动保存。
- 重要内容有版本历史。
- AI 生成内容不应直接覆盖用户原文，必须可预览、可撤销。

### 6.3 隐私与安全

- 用户作品内容默认私有。
- AI 调用需要明确告知发送了哪些上下文。
- 后续商业版需支持本地模型或私有化部署方向。

### 6.4 可迁移性

- 支持 Markdown / TXT 导出。
- 后续支持从本地文件夹、旧项目、知识库导入。
- 内部数据结构应避免绑定单一平台。

### 6.5 可扩展性

- AI 能力应以任务和上下文管线组织，而不是散落在组件中。
- 作品数据、设定数据、素材数据需要有清晰边界。
- 后续能扩展到桌面端、协作版和素材市场。

## 7. 暂不进入 MVP 的需求

以下需求有价值，但不应进入第一版 MVP：

- 多人实时协作。
- 插件市场。
- 完整平台数据自动抓取。
- 自动发布到各网文平台。
- 多模型复杂调度。
- 完整桌面离线版。
- 大规模素材交易市场。
- 自动生成整本书。

原因：这些能力工程复杂度高，且在证明核心写作工作流之前容易拖慢产品验证。

## 8. MVP 优先级结论

第一阶段应优先完成：

1. 作品项目管理。
2. 章节树与正文编辑器。
3. 人物库与设定库。
4. 右侧 AI 助手面板。
5. 章节总结、续写、润色、改写。
6. 基础上下文组装。
7. TXT / Markdown 导出。

第一阶段验收标准：

- 用户可以在平台中从零创建一本书。
- 用户可以建立至少 10 个章节并持续写作。
- 用户可以维护人物和设定。
- 用户可以让 AI 基于当前章节和基础设定进行辅助。
- 用户可以导出可发布文本。
