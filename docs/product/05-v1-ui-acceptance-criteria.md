# V1 UI 验收标准

版本: v0.1
日期: 2026-05-27
阶段: V1 UI 原型完善
研发分支: v1-development

## 1. 文档目标

本文件用于重新明确当前研发分支的主目标：优先完成 Webnovel IDE 的商业级 UI 原型，而不是在本分支深入实现完整业务功能。

当前分支的验收重点是：

- 信息架构是否清晰。
- 页面是否像一个专业 IDE。
- 深色与浅色主题是否统一。
- 核心入口是否合理。
- 交互壳是否完整。
- 后续功能模块是否有清晰预留位置。

具体业务能力，例如真实 AI 调用、复杂章节复盘、知识库、连续性检查、团队协作、发布平台对接，不作为本分支完成目标。

## 2. V1 UI 原型目标

V1 UI 原型需要让用户在第一眼感受到：

> 这是一个围绕长篇网文创作构建的专业写作 IDE，而不是普通文档编辑器，也不是简单 AI 聊天工具。

UI 原型必须支持以下演示路径：

```text
进入作品列表
  ↓
创建或进入作品
  ↓
进入三栏 IDE 工作台
  ↓
查看章节树
  ↓
编辑章节
  ↓
打开应用设置
  ↓
切换深色 / 浅色主题
  ↓
打开右侧助手
  ↓
看到 AI、人物、设定等后续能力入口
```

## 3. 总体验收原则

## 3.0 UI 验收执行逻辑

V1 UI 验收采用“层级优先，功能点辅助”的逻辑。

验收顺序如下：

```text
全局视觉系统
  ↓
页面框架
  ↓
区域布局
  ↓
组件状态
  ↓
具体功能入口
```

### 第一层：全局视觉系统

先验收整个应用是否统一：

- 深色 / 浅色主题。
- 字体层级。
- 间距规则。
- 圆角、边框、阴影。
- 主色、危险色、选中态。
- 输入框、按钮、弹窗、菜单的统一样式。

只有这一层稳定后，后续页面修补才不会反复返工。

### 第二层：页面框架

再验收页面骨架：

- 作品列表页。
- 工作台。
- 应用设置。
- 弹窗系统。

这一层关注页面是否像一个完整产品，而不是单个按钮是否可用。

### 第三层：区域布局

然后验收每个页面内的区域：

- 顶部栏。
- 活动栏。
- 左侧资源管理器。
- 主编辑区。
- 右侧助手。
- 状态栏。

这一层关注信息密度、层级、对齐、滚动、是否拥挤。

### 第四层：组件状态

再验收通用组件：

- 普通按钮、主按钮、危险按钮。
- 输入框、下拉框、文本域。
- Tab、卡片、菜单、弹窗。
- hover、active、focus、disabled。
- 空状态、选中态、拖拽态。

这一层确保组件在所有主题下都稳定。

### 第五层：具体功能入口

最后才验收功能入口摆放是否合理：

- 新建作品。
- 新建卷 / 章节。
- 应用设置。
- 作品设置。
- 导出。
- 打开助手。
- AI 配置壳。

当前分支只验收入口和交互壳，不验收复杂业务结果。

### 3.1 视觉统一

- 同一主题下不得出现明显割裂的色块。
- 深色主题中，输入框、编辑器、弹窗、菜单不应突然出现大面积纯白。
- 浅色主题中，侧栏、顶栏、编辑区不应保留重度深色残留。
- 按钮、输入框、卡片、弹窗、菜单的圆角、边框、阴影、间距应统一。
- 字体层级清晰，不使用夸张的营销式大标题。

### 3.2 IDE 感

- 工作台应优先像专业工具，而不是官网首页。
- 信息密度应适中，避免按钮堆叠。
- 左侧资源管理器、顶部栏、编辑器 Tab、状态栏应形成稳定的 IDE 框架。
- 常用操作应显性，低频操作应进入菜单、右键菜单或设置。
- 页面不应依赖说明文字解释怎么使用。

### 3.3 写作体验

- 中间编辑区应是视觉焦点。
- 正文输入区域应安静、稳定、不抢注意力。
- 章节标题、状态、字数、章节目标的位置应符合写作流程。
- AI 与上下文能力应辅助写作，而不是挤压写作区域。

### 3.4 可扩展性

- 全局设置必须能继续扩展新分类。
- 右侧助手必须能承载后续 AI、人物、设定、复盘、连续性检查等模块。
- 左侧资源管理器必须能继续扩展大纲、伏笔、时间线、素材等模块。
- 当前 UI 壳不应封死后续商业功能。

## 4. 页面级验收标准

### 4.1 作品列表页

必须满足：

- 页面视觉风格与工作台主题一致。
- 顶部品牌、作品标题、新建作品、应用设置入口清晰。
- 空状态在深色和浅色主题下都完整可读。
- 作品卡片信息层级清楚，包括作品名、简介、题材、平台、章节数、字数、更新时间。
- 卡片按钮位置稳定，不因内容长短明显跳动。
- 不出现营销官网式大 hero 区。

验收状态：

- [ ] 深色主题通过。
- [ ] 浅色主题通过。
- [ ] 空状态通过。
- [ ] 多作品列表通过。
- [ ] 长标题 / 长简介不破坏布局。

### 4.2 作品工作台

必须满足：

- 顶部栏、活动栏、资源管理器、主编辑区、状态栏结构稳定。
- 当前作品名、当前章节名、保存状态、字数信息清晰。
- 右侧助手默认可隐藏，打开后不压垮主编辑区。
- 工作台在 1366px、1440px、1920px 桌面宽度下可用。
- 不出现按钮拥挤、文字重叠、横向溢出。
- 滚动区域清晰，不出现多个滚动条互相干扰。

验收状态：

- [ ] 深色主题通过。
- [ ] 浅色主题通过。
- [ ] 右侧助手关闭状态通过。
- [ ] 右侧助手打开状态通过。
- [ ] 1366px 宽度通过。
- [ ] 1920px 宽度通过。

### 4.3 左侧资源管理器

必须满足：

- 章节、人物、设定、导出等分区层级明确。
- 卷和章节的视觉关系清楚。
- 当前选中章节高亮明确。
- 章节拖拽排序有可感知反馈。
- 低频操作进入右键菜单，减少显性按钮数量。
- 分区为空时有合理空状态或创建入口。

验收状态：

- [ ] 章节树通过。
- [ ] 卷右键菜单通过。
- [ ] 章节拖拽反馈通过。
- [ ] 人物空状态通过。
- [ ] 设定空状态通过。
- [ ] 导出区域通过。

### 4.4 主编辑区

必须满足：

- 章节标题、状态、章节目标、正文编辑区层级清晰。
- 编辑器背景与当前主题统一。
- 正文区域足够宽、足够高，适合长文输入。
- 工具栏按钮数量克制，核心操作优先。
- 删除等危险操作有明显但不过度突兀的视觉表达。
- 字数统计位置稳定。

验收状态：

- [ ] 深色编辑器通过。
- [ ] 浅色编辑器通过。
- [ ] 长章节标题通过。
- [ ] 空正文状态通过。
- [ ] 长正文滚动通过。
- [ ] 工具栏不拥挤。

### 4.5 右侧助手 / 上下文面板

必须满足：

- 右侧面板不是强制常驻。
- 打开后能清晰承载当前章节、人物、设定、AI 助手等模块。
- AI 输出区域、输入区域、操作按钮布局稳定。
- 后续章节复盘、连续性检查、伏笔提醒等能力有预留空间。
- 面板在窄屏下不破坏主编辑区。

验收状态：

- [ ] 默认隐藏通过。
- [ ] 打开状态通过。
- [ ] AI 面板壳通过。
- [ ] 当前章节信息壳通过。
- [ ] 人物 / 设定上下文壳通过。

### 4.6 应用设置

必须满足：

- 应用设置作为全局设置入口，不再让 AI 配置孤立漂浮。
- 设置弹窗居中稳定，不横向溢出。
- 设置内容超高时内部滚动。
- 标签页结构清晰，可扩展外观、AI、编辑器、快捷键、数据、账号等分类。
- 深色 / 浅色主题切换卡片清晰、可点击、选中态明确。
- AI 配置只作为 UI 壳验收，不要求真实调用。

验收状态：

- [ ] 弹窗尺寸通过。
- [ ] 外观标签通过。
- [ ] AI 标签通过。
- [ ] 深色主题切换通过。
- [ ] 浅色主题切换通过。
- [ ] 小高度窗口滚动通过。

### 4.7 弹窗与菜单

必须满足：

- 所有弹窗风格统一。
- 弹窗标题、关闭按钮、取消按钮、主按钮位置一致。
- 右键菜单风格与主题一致。
- 菜单不超出视口边界。
- 危险操作使用统一危险色。
- focus、hover、active 状态清晰。

验收状态：

- [ ] 新建作品弹窗通过。
- [ ] 新建卷弹窗通过。
- [ ] 新建章节弹窗通过。
- [ ] 新建人物弹窗通过。
- [ ] 新建设定弹窗通过。
- [ ] 作品设置弹窗通过。
- [ ] 应用设置弹窗通过。
- [ ] 右键菜单通过。

## 5. 主题验收标准

### 5.1 深色主题

必须满足：

- 主背景、侧栏、顶栏、状态栏、弹窗、输入框统一深色。
- 输入框和文本区域不出现大面积纯白。
- 文本对比度足够，正文、按钮、标签均清晰可读。
- 激活态、hover 态、危险态、主按钮态清晰可辨。
- 编辑器长期写作不刺眼。

验收状态：

- [ ] 作品列表深色通过。
- [ ] 工作台深色通过。
- [ ] 编辑器深色通过。
- [ ] 弹窗深色通过。
- [ ] 右键菜单深色通过。

### 5.2 浅色主题

必须满足：

- 主背景、侧栏、顶栏、状态栏、弹窗、输入框统一浅色。
- 不保留明显深色主题残留。
- 边框和层次清楚，不能变成一片白。
- 选中态、hover 态、主按钮态清晰。
- 长时间阅读和整理设定时舒适。

验收状态：

- [ ] 作品列表浅色通过。
- [ ] 工作台浅色通过。
- [ ] 编辑器浅色通过。
- [ ] 弹窗浅色通过。
- [ ] 右键菜单浅色通过。

## 6. 交互壳验收标准

当前分支只验收交互壳，不验收复杂业务结果。

必须满足：

- 点击入口后有合理反馈。
- 无功能的入口可以使用 mock、占位态或本地提示。
- 禁用状态明确，不让用户误以为功能坏了。
- 表单基础校验可用。
- 危险操作需要确认。
- 页面刷新后主题与基础数据保留。

验收状态：

- [ ] 新建类操作反馈通过。
- [ ] 设置保存反馈通过。
- [ ] 主题持久化通过。
- [ ] 右侧助手开关通过。
- [ ] 章节拖拽视觉反馈通过。
- [ ] 导出入口位置通过。

## 7. 不纳入本分支的内容

以下内容不作为本分支完成目标：

- 真实 AI Provider 调用。
- 服务端 API。
- 数据库。
- 登录注册。
- 团队协作。
- 权限系统。
- 发布平台对接。
- 章节自动复盘完整流程。
- 连续性检查。
- 知识图谱。
- 素材库和拆书系统。
- 复杂富文本编辑器。

这些功能可以在 UI 壳中预留入口，但不在本分支深做。

## 8. V1 UI 完成定义

当以下条件全部满足时，当前 UI 分支可以认为达到 V1 UI 原型验收：

- [ ] 作品列表页深色 / 浅色均通过。
- [ ] 工作台深色 / 浅色均通过。
- [ ] 主编辑区深色 / 浅色均通过。
- [ ] 应用设置深色 / 浅色均通过。
- [ ] 所有弹窗不溢出、不重叠。
- [ ] 页面在 1366px 与 1920px 宽度下可用。
- [ ] 主要入口位置稳定且不重复。
- [ ] 用户可以完整演示一条从作品列表到工作台再到主题切换的路径。
- [ ] 没有明显廉价感、临时感或功能按钮堆叠感。

## 9. 下一步建议

后续 UI 工作按以下顺序推进：

1. 修复当前深色主题残留白块与弹窗溢出问题。
2. 完整打磨应用设置弹窗。
3. 打磨工作台主编辑区。
4. 打磨左侧资源管理器。
5. 重新设计右侧助手区域。
6. 补齐所有空状态、hover、active、focus、disabled 状态。
7. 做深色 / 浅色双主题逐屏验收。
