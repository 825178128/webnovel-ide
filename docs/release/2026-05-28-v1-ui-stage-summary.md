# V1 UI 阶段总结

日期: 2026-05-28
分支: v1-development
阶段: V1 UI 原型封版前总结

## 1. 阶段目标

本阶段目标是完成商业级中文网文 IDE 的 V1 UI 原型，而不是深入实现完整业务功能。

本分支重点解决：

- 产品是否像专业 IDE，而不是普通文档工具或简单 AI 聊天页。
- 工作台是否形成稳定的顶部栏、活动栏、资源管理器、主编辑区、右侧面板、状态栏结构。
- 深色 / 浅色主题是否统一。
- 章节、人物、资料、设置、导出、右键菜单等核心入口是否形成可演示交互壳。
- 后续 AI、章节复盘、连续性检查、知识库等商业功能是否有清晰承载位置。

不在本分支完成：

- 真实 AI Provider 调用。
- 后端 API、数据库、登录注册。
- 发布平台对接、团队协作、权限系统。
- 章节自动复盘完整业务流程。
- 复杂富文本编辑器。

## 3. 设计思路

### 3.1 专业 IDE 优先

V1 UI 不采用官网式 hero、营销卡片堆叠或聊天工具布局，而是使用工具型产品框架：

- 左侧活动栏承载大模块切换。
- 资源管理器承载章节、人物、资料和导出入口。
- 中央区域优先给写作或当前实体编辑。
- 右侧面板承载属性、上下文、AI 等辅助能力。
- 底部状态栏承载自动保存、字数、资源统计。

### 3.2 写作焦点优先

章节编辑页减少顶部重复信息和按钮密度，正文区域保持稳定、安静、可长时间写作。

章节目标、状态、摘要、人物关联、资料关联等辅助信息放在右侧，不挤压正文。

### 3.3 低频操作收纳

导出、重命名、删除、卷操作等低频操作尽量进入菜单或右键菜单，避免主界面按钮过多。

危险操作使用统一危险色，并保留确认逻辑。

### 3.4 双主题作为系统能力

主题不只是局部换色，而是通过 CSS 变量贯通页面背景、侧栏、输入框、弹窗、菜单、卡片、阴影和状态色。

### 3.5 功能壳先行

AI、复盘、连续性检查等能力先有明确入口和承载区，真实业务逻辑留给后续功能分支。

## 5. 当前风险

- 当前仍是前端本地原型，数据持久化为本地存储。
- AI 配置只作为 UI 壳，不应被理解为真实安全调用方案。
- 章节编辑仍是普通 textarea，后续如需富文本、Markdown、快捷键体系，需要单独设计。
- UI 未接入自动化视觉回归测试，最终视觉判断依赖人工目测。

## 6. 合并建议

建议将 `v1-development` 合并到主分支，作为 V1 UI 原型基线。

合并后建议立即创建新的后续分支，避免在 UI 封版分支继续混入功能开发。

推荐后续分支方向:

- `v1-data-persistence`: 数据持久化与项目文件结构。
- `v1-editor-core`: 编辑器能力、快捷键、自动保存状态。
- `v1-ai-context-shell`: AI 上下文组装和服务端代理设计。
- `v1-continuity-system`: 章节复盘、连续性检查、伏笔追踪。
